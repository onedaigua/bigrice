# DSH 0.2.2-rc.4 适配记录（0.1.30 → 0.1.31）

这份文档记录升级到 DSH 0.2.2-rc.4 后，bigrice-ui 在手机视口上暴露的问题、宿主发生的变化、
以及 0.1.31 的修法和验证方式。后续 DSH 再升级时可以照这个流程回归。

## 1. 宿主侧变化

| 变化 | 影响 |
| --- | --- |
| `AppFrame` 在 `viewport < 768` 自带抽屉（`data-sidebar-drawer`、`.drawerMask`，`sidebarCol` 绝对定位、`z-index: 71`） | 插件原本在 <1024 自己做抽屉，窄屏上两套抽屉/遮罩叠加 |
| 新增 `shell.leading` 槽，drawer 模式下渲染宿主汉堡按钮（`[data-shell-leading]`） | 与插件顶栏的 Menu 按钮重叠在同一位置 |
| `SIDEBAR_AUTO_COLLAPSE = 1024`，768–1024 走 `narrowExpanded` 窄轨道 | 插件 1024 阈值与宿主 768 阈值不一致，中间区间行为错位 |
| 会话标题行用 `--dsh-frame-leading-clearance` 预留左侧空间（drawer 84px，否则 48px） | 插件再叠 34px `padding-left` 变成重复缩进 |
| 设置弹窗改为 grid 四子节点：`div.navTitle` / `nav > div.navList` / `div.header` / `div.options` | 插件按旧的 `nav > div:first-child` 取标题、`> div > [class*='header']` 取关闭按钮全部落空 |
| ≤767px 设置页由宿主切成全屏单列（`areas: title header / nav nav / options options`，`navList` 横向滚动） | 插件仍按桌面两栏改写，且 `[role=presentation]` 的 12px padding 让全屏页缩成浮卡 |
| popover 改用 CSS anchor 定位（`position-anchor`） | 插件依赖 `style*='left'` 的居中规则永不命中；通用 `[role=dialog]` 宽度会把锚定层撑到 520px |
| 主题 token 改名：`--dsw-alias-text-primary` → `--dsw-alias-label-primary` | 插件里的一处文字色失效 |
| `layout.panelInfo` 只暴露 `getSnapshot()/subscribe()` | 插件的 `panelInfo.get()` 调用无效（有 try 兜底，不至于崩） |

## 2. 复现与修复对照

| # | 症状（412×915） | 根因 | 0.1.31 修法 |
| --- | --- | --- | --- |
| R-01 | 左上角两枚汉堡叠成花，`elementFromPoint(26,25)` 命中插件 SVG | 插件 `.bigrice-topbar`（`0,10,412,30`，`z-index:50`）的 44×44 按钮与宿主 leading（28×28 @ `12,11`）重合 | 探测 `[data-shell-leading]` → `data-bigrice-hostdrawer`，隐藏 `.bigrice-topbar` |
| R-02 | 抽屉打开后左上角点不到关闭，只能点遮罩 | 插件抽屉 `z-index:60`、宿主抽屉 `z-index:71`，插件按钮被压住 | 同上，改用宿主 leading 开合 |
| R-03 | 打开抽屉出现两层遮罩，点遮罩只关宿主，再点 Menu 无效 | 宿主 `.drawerMask` 与插件 `.bigrice-mask` 同时存在，插件状态标志与宿主失步 | 隐藏 `.bigrice-mask`；`data-bigrice-drawer` 改为镜像 `frame[data-sidebar-collapsed]`，不再自持状态 |
| R-04 | 700px 下双栏双遮罩；900px 下插件有栏、宿主无按钮 | 两个断点（1024 / 768）不一致 | 保留 768–1024 自有顶栏，<768 让位宿主 |
| R-05 | 插件市场 Recent 卡片右缘 464 > 412 被裁 | 插件 `[role=dialog]` 宽度规则误伤卡片 | 通用对话框选择器加 `:not([style*='position-anchor'])` |
| R-06 | 设置弹窗在手机上被 12px 内缩、非全屏 | `[role='presentation']:has(> [role='dialog']) { padding:12px }` | 给 `data-shortcut-modal='settings'` 的 dialog 加 `padding:0 !important` 例外 |
| R-07 | 右侧面板在窄屏打不开/0 宽 | `rightbarCol` 在手机下被插件改成绝对定位，宿主 rect 为 0 | 保持为全屏浮层（内容 412×915），确认可交互 |

另有若干随升级失效的静态选择器/token：`--dsw-alias-text-primary`、`fieldset[class*='registrySheet']`、
`[class*='installSource']`、`panelInfo.get()` —— 0.1.31 一并收敛到新名字或新 API。

## 3. 关键实现点

- **让位探测**：`sync()` 里 `document.querySelector('[data-shell-leading]') !== null` 决定是否进入
  `data-bigrice-hostdrawer` 模式；该模式下同时关闭 `stretchSidebar()` 与 `syncHeaderRow()`，
  把标题行缩进完全交给宿主的 `--dsh-frame-leading-clearance`。
- **状态镜像**：抽屉开合仍调用宿主 `layout.toggleSidebar()`；`data-bigrice-drawer` 只用于插件自己的
  阴影/过渡样式，值来自 `!frame.hasAttribute('data-sidebar-collapsed')`。
- **设置页**：桌面改写包进 `@media (min-width:768px)`；选择器改为
  `> div[class*='navTitle']`、`> nav > div[class*='navList']`、`> div[class*='header']:not([class*='navTitle'])`，
  并给 panel 加 `display:flex` 抵消宿主的 grid 定义。

## 4. 验证

用零依赖 CDP 驱动无头 Chromium（`chromium-1091`，`--headless=new`），
`Emulation.setDeviceMetricsOverride` 开 412×915 / 700×915 / 900×915（DPR 3，`mobile:true`），
注入 CJK 字体后逐页截图并量 DOM：

- 412：`html` 上只有 `data-bigrice-mobile` + `data-bigrice-hostdrawer`；`.bigrice-topbar` 为 `display:none`；
  宿主 leading 28×28 @ `12,11`；`.bigrice-mask` 不存在；宿主 `.drawerMask` 开 `opacity:1` / 关 `0`；
  开抽屉后 `data-bigrice-drawer` 出现、关闭后移除；设置页 `412×915 @ 0,0`，`navList` 横向滚动
  （`scrollWidth 1164 / client 412`），bigrice 页签可点开。
- 700：宿主抽屉接管，插件栏隐藏，无双遮罩。
- 900：宿主无 leading，插件顶栏 `900×30` 正常显示，菜单按钮 44×44，无重叠。
- 控制台：除宿主自身的 `archive-manager` / `deepseek-account` 旧告警外，无异常。

## 5. 落地方式

插件在 app 内的安装目录是 `/opt/bigrice-ui`，profile 以 `link:` 引用。补丁直接改
`/opt/bigrice-ui/client.js`，然后刷新页面（rev = mtime+ctime+size）。

**APK 升级会覆盖它**：启动安装器会重新解包自带的 `bigrice-ui.tar` 并刷新
`/opt/bigrice-ui.sha256`。升级后需要重新打补丁；本仓库保留完整 0.1.31 内容，可作为补丁源。
