## 两个独立可用的包（历史原文）

两个独立可用的包：

| 目录 | 是什么 | 怎么用 |
| --- | --- | --- |
| [`bigrice-app/`](bigrice-app/README.md) | Android 应用 `bigrice-release.apk`（2.14 MB，其中 1.66 MB 是启动动画；Debian rootfs 与 Node 在首次启动时联网下载，APK 里只有 proot 引导）。启动时自动装 Node.js 与 DeepSeek Harness，并把它的网页界面全屏显示。 | 装到 arm64 手机上，首次启动联网等 3–4 分钟 |
| [`bigrice-ui/`](bigrice-ui/README.md) | 手机界面插件 `bigrice-ui`（28 KB 源码 + 安装用 tar）。给 DeepSeek Harness 补上手机布局：抽屉会话列表、贴底输入框、全屏设置、横竖屏适配、返回键逐级后退。 | bigrice 里已预装，不用管；装到别的 dsh 时按它自己的 README 走 |

两者关系：`bigrice-app` 负责「在一台手机上跑起 DeepSeek Harness」，`bigrice-ui` 负责「让它的界面在手机上能用」。它们可以分开用——插件也能装到电脑版 dsh 上，只是不生效（它按宿主框架的实际宽度判断，桌面窗口下不触发）。

## 最短上手

```bash
adb install -r bigrice-app/bigrice-release.apk
# 打开 bigrice，等进度走完（解包 → 装 Node/dsh → 启动 dsh web）
# 左上 ☰ → … 更多 → 设置 → 模型 → 填 DeepSeek API Key → 保存
# 回到会话页，开始对话
```

详细说明、常见问题（网络、`REJECT_ALL`、登录不通）、构建与签名，都在两个子目录的 README 里。

## 目录约定

这个仓库只有两个文件夹，每个都是一个自包含的包——源码、可交付物、说明放在一起，删掉另一个也不影响它继续被构建/使用：

```
bigrice-app/    Android 应用：APK + 工程源码（app/）+ 安装脚本 + 开发工具
bigrice-ui/     手机界面插件：打包好的 tar + 源码 + 说明
README.md       本文件
```

`bigrice-app/app/assets/` 里只有跑起来需要的几样东西：`proot` + 两个 `.so` + `loader`、安装脚本 `install.sh`、注册脚本 `register-bundle.js`、插件包 `bigrice-ui.tar`、启动动画 `boot.gif`。Debian rootfs、Node、npm 依赖都是首次启动时从镜像流式下载（`MirrorProbe` 先测速），所以 APK 里没有大文件。

## 版本

当前主线是 **bigrice-native a2.3**：不再用 proot + Arch rootfs，APK 里直接带原生 node 运行时（`bigrice-native/`）；旧版 proot 包（`bigrice-app/`，a1.8）保留可用，但不再更新。

- bigrice **a2.3**（versionCode 203，`com.bigrice`，minSdk 26 / targetSdk 28）— 原生运行时 + 直接跑 dsh
- bigrice a1.8（versionCode 180）— proot + Arch Linux ARM rootfs，旧包
- bigrice-ui **0.1.33**，随 APK 的 `assets/bigrice-ui.tar` 打包（不再从 git 自动更新）
- dsh **跟随 npm 最新版**（当前 0.2.2-rc.5），更新只在设置 → bigrice → 更新卡片里手动触发

## a2.3 改了什么

- **工作区路径变短、环境目录搬出外部存储**：工作区就是 `/storage/emulated/0/Android/data/com.bigrice/work`（以前是 `files/work/deepseek-harness/default-workspace`，还套着 dsh 自动建的一级），node 运行时、下载的 dsh 版本、`DSH_HOME`、插件、`HOME` 全在内部 `/data/user/0/com.bigrice/files` 下，外部只剩工作区一个目录。老版本首次启动会把旧内容摊平并迁移，旧会话归档到 `dsh-home/sessions-legacy/`（改名会让 dsh 判 corrupt）。
- **工作区注册表只剩一条**：`workspace.json` 重写成 path=新工作区、title=`work`；dsh 在 HOME 下自动建的字母工作区（proot 时代的 `/root/A`）不再出现在工作区列表里。
- **修掉工作区里长镜像目录树**：`HostBridge` 的 `rel()` 以前把外部绝对路径当相对串处理，于是每次启动都会在 `work/` 里建出 `storage/emulated/0/Android/data/com.bigrice/work/download`；现在只接受工作区内的绝对路径、导入目录改传相对路径 `download`，启动时还会清理历史空壳。

## a2.2 改了什么

- **首启的下载进度条真的走起来了**：`onUpdate` 一直带着 pct，但开屏页每 300 ms 被 `poll` 的 `showPill("正在启动…")`→`bootStage`→`indeterminate` 覆盖回扫动。现在 `BootScreen.percent()` 一旦写过真实百分比就置 `precise`，`indeterminate()/band()` 在 `precise` 期间直接忽略；命中 npm 缓存（不打 `http fetch`）时按时间爬（≈40 s 到 74%，封顶 87），所以条不会卡在 44% 不动。
- **首启不再起两个 dsh**：bootstrap 的 `phase=done` 原来会触发 `restartDsh()`，把刚 spawn 的进程杀掉重来（实测一次冷启两个 dsh、两个端口、一次 `selfcheck npm 失败: InterruptedException`）。现在 `DshService.bootstrapping` 期间跳过重启，服务自己接着 spawn 新版。

## a2.1 改了什么

- **通知只在后台出现**：回到 a1.0 的行为。`MainActivity.onStart/onStop` 调 `DshService.uiVisible()`，前台时 `stopForeground(REMOVE)` 把卡片收起来，退后台再 `startForeground`。服务 `onCreate` 仍先进一次前台（系统要求 5 秒内），随即按可见性收起。
- **通知会说清"现在在干什么"**：旧捕获只认 `[data-state]` 的 running/pending，但实测 dsh 0.2.2-rc.5 里那个属性只写 `ok`/`error`（已结束的行也带着），所以卡片长期停在「dsh 后台运行中」。现在按「发送按钮变『停止生成』→ `[data-process-activity]` 里以『正在』开头的活行 → `[data-state]` 兜底」判定，并带上会话标题：一个回合跑起来后按 HOME，卡片显示 `Greeting · 正在运行命令`（14 次采样全中），空闲时回到 `dsh 后台运行中`。

## a2.0 改了什么

- **原生 node，不再 proot**：APK 自带 `libnode.so` + 引导包，首次启动只下载 dsh 本体；启动从分钟级降到秒级，包体也从三件套（rootfs + node + dsh）缩到 ~35 MiB。
- **默认工作区能建出来了**：dsh 在 `process.platform === "android"` 下取系统「文档」目录必然抛错，所以启动时带一层 profile patch（`assets/dsh-workspace.yml` + `BIGRICE_DOCUMENTS`），默认工作区落在应用私有目录，聊天输入框不再被「无法创建默认工作区」挡住。
- **更新只手动**：启动不检查、不下载；设置 → bigrice 的「更新」卡片里有「检查更新 / 安装最新版」，进度写在卡片里。检查更新只查 npm，不重启 dsh；只有真装了新版本才会重启一次。
- **下载回到 a1.0 的做法**：先对镜像做 256 KB 吞吐测速挑最快节点（手机 WiFi 上腾讯 494 KB/s 对 npmjs 116 KB/s），npm 用 `--maxsockets=64` 多线程拉包，进度按真实 `.tgz` 计数走百分比（开屏页那条 bar 现在是真进度，不再只扫动）。
- **回到 bigrice 的样子**：启动图标换回 bigrice 那套（自适应 mipmap + 单色状态栏图标），通知栏恢复成一张常驻卡片（`bigrice` + 当前阶段/当前动作 + 「停止」），不再是系统下载图标、也不再被塞进「静音」分组。
- **进界面变快**：dsh 进程还活着就直接复用它的 URL（界面重建 ~1 s，不再重复起 node；进程在而 Activity 被回收时服务会补发一次 URL 广播）；开机 / 更新后由 `BootReceiver` 提前把服务拉起来；服务比 WebView 先起，开屏页在页面 `progress=100` 后 220 ms 收起。冷启动仍要等 node 起 dsh（~7 s），这部分没动。

## a1.8 改了什么

- **悬浮球整块去掉了**：桌面不再留球、不再弹气泡、不再要「显示在其他应用上层」权限，`FloatWindow.java`、`SYSTEM_ALERT_WINDOW` 和桌面捷径 `shortcuts.xml` 一起删掉。界面只剩「在应用里」和「在后台」两种形态。
- **回到下拉通知栏**：`KeepAlive` 重新是前台服务，一条常驻卡片（`bigrice` + 当前阶段/当前动作）。界面在前台时不发，退到后台才出现；点卡片回到会话。
- **只剩一条**：启动时原本开屏页一条、服务一条，通知栏里并排成「bigrice · 2」；现在 `BootScreen` 的 `Notifier` 只把阶段文字转给 `KeepAlive`，卡片归服务独有。启动中途按 Home，看到的就是那一条，文字跟着「检查 dsh 更新 → 等待 dsh web 就绪」走，页面加载完写「已就绪」4 秒后清空。
- **空闲就是空的**：对话没有动作时卡片只有 `bigrice`，第二行整行不出现。

## a1.7 改了什么

- **球只负责开关消息，不会再自己跳进软件**：点球永远是「显示消息」，收起消息之后再点球，还是显示消息；只有点在消息气泡里那颗圆形图标上（也就是球原来的位置）才会 `float open app` 进应用。
- **手动收起就真的收起了**：启动阶段 `stage()` 每一条（下载 → 解包 → 装 Node → 起 dsh web）都会更新状态行，以前状态一变，刚收起的气泡又自己弹开，关不掉；现在手收一次就静音，直到状态清空或者自己点球重新打开。
- **拖动不再算点击**：判定从「每个轴位移 > 6dp」换成欧氏距离，斜着拖 20px 之前每轴只有 14px，会被当成点击，于是在气泡图标上拖一下就进了软件；现在只要动过就是拖动，只会挪位置、贴边。
- **「已就绪」只是通知，不是一个状态**：页面加载完后气泡自己展开 4 秒，然后把位置让回球，桌面上留一颗球而不是一直挂一张卡片。

## a1.6 改了什么

- **下拉通知栏里没有 bigrice 了**：原来那条常驻通知是为前台服务服务的，`KeepAlive` 现在是普通服务，只负责把进程留在内存里，一条通知都不发；启动进度也只在开屏页显示。进程靠「屏幕上有东西」活着——界面在前台，或者桌面上那颗球/那张气泡在画。
- **启动中途退出也能看到东西**：页面还没起来（首次还在下载/解包）时按 Home，原来什么都留不下；现在桌面上会出现一张启动卡片（同样的胶囊形，写着当前阶段，比如「安装 Node」），页面就绪后它自己换成悬浮球（日志 `悬浮球：接替启动提示`）。
- **球自己会说话**：启动完成后球自动展开成消息，第二行写「已就绪」；对话跑起来就换成「正在调用工具 bash」或「思考中…」，跑完自动收起回球。不用点，看一眼就知道在干什么。
- **点法**：点球 → 弹出消息；点消息正文 → 收起、变回球；长按球仍然进那块可拖可缩的小窗（a1.7 把「再点球进软件」改掉了，见上）。
- 通知卡片里那行字仍然由页面里的 `[data-state]`（工具行、思考行）每 1.5 秒轮询出来，现在只喂给气泡，不再写通知栏。

## a1.5 改了什么

- **退到后台留一颗球**：按 Home、从桌面捷径「悬浮球运行」启动，界面都折成 56dp 的圆球贴到最近的一边，不再是一上来就摆一块小窗挡在别人应用上面。球里的应用图标按圆裁剪（`CircleIcon` + `BitmapShader`），圆外是背景而不是方图标的四块黑角。
- **点球弹出通知气泡**：气泡就是通知卡片的桌面版——图标 + `bigrice` + 一行状态，宽 232dp；对话空闲时只有 `bigrice`，第二行整个不出现（「对话已经完成就显示为空」）。
- **状态从页面里取**：每 1.5 秒在页面里查一次 `[data-tool][data-state]` 与 `[data-streaming]`，正在跑工具就显示「正在调用工具 bash」，生成中就显示「思考中…」；同一行字符串同时写进通知卡片，通知栏和气泡永远一致。
- **再点气泡直接进应用**：气泡上没有展开按钮（`⤢` 去掉了），点一下就是 `float open app` → 收窗 → `MainActivity` 到前台，一步看到完整会话。想边干活边看对话，**长按球**仍能拿回原来的小窗（小窗的 `▾` 又能折回球）。
- **通知点开即会话**：通知卡片不再带「以小窗继续」的意图，点卡片就是打开应用本身。
- 走位：屏幕坐标仍以 `frame.getLocationOnScreen` 打出的 `float folded/notice/open app` 日志为准（系统会把浮窗按状态栏「塞」一次，`mAttrs.y` 不是可见顶边）。

## a1.4 改了什么

- **界面插件从 git 源更新**：`update-ui.sh` 启动时先对仓库 `main` 的压缩包发一个 HEAD，拿回的 `ETag` 就是该提交的摘要；和 `/opt/bigrice-ui.git` 里记的一致就直接结束（一次请求、几秒）。不一致才读 `package.json` 比版本、下载 tarball（几十 KB），校验版本后整目录替换 `/opt/bigrice-ui`。因此**没有版本号的修复也会被拉下来**。APK 里的 `bigrice-ui.tar` 退化成「首次启动的快照」，之后不再回写 —— 换插件不用重装 APK。
- **自动找能用的 git 源**：raw.githubusercontent → jsdelivr → gh-proxy → ghfast → raw.gitmirror 依次探测版本；下载走 codeload → 四个镜像，全挂就保留本地版本继续启动。
- **更新失败能回滚**：新包先落到 `/tmp`，验证 `client.js`、`package.json`、版本号都在才替换；替换或复制中途出错就把旧目录 `mv` 回来，日志里打 `#ui update rolled back`。
- **dsh 不指定版本**：`update-dsh.sh` 只认「源上最新」（`latest`/`next` 与全部版本按 semver 排序取最新），装不上才退到次新；手机自己下载，电脑不参与。
- 启动顺序：`install()` → 同步 APK 里的插件快照（有 git 标记就跳过）→ `updateDsh()` → `updateUi()` → `dsh web`。

## a1.3 改了什么

- **dsh 自动更新**：APK 里的 `dsh-lock.json.gz` 只保证首次安装快，之后每次启动用一条约 10 KB 的元数据请求比对 npm 上的最新版，比本地新就整棵树换掉；旧树先 `mv` 成 `@deepseek-ai.bak`，失败原样搬回，所以半截的依赖树不会留到下一次启动。
- 手机自己从 npm 源下载，日志里逐段打印「已取 N 个包」。

## a1.2 改了什么

- **悬浮窗**：应用退到后台（按 Home 或切到别的应用）时，界面不是消失，而是缩成一块浮在桌面上的小窗继续跑 —— 同一个 WebView、同一段对话、输入框里没发出去的字、滚动位置都还在。小窗有 42dp 的标题条：拖标题条移动、`⤡` 拖动改大小、`⤢` 回全屏、`✕` 关掉（进程留着，dsh 继续跑）。回到应用时它自动收回去，不会出现两个界面。
- **缩到和图标一样大**：标题条右端 `▾` 把窗口折成 56dp 的圆点（用应用图标），贴到离它最近的那一边；点一下还原成原来的大小和位置，拖它可以换边。
- 悬浮窗需要「显示在其他应用上层」权限：第一次浮起来会直接跳到授权页，给完再退回应用就出小窗。
- 小窗里能正常打字：点输入框键盘弹出时整块窗口抬到键盘上方，收键盘后回到原位；Back 只收键盘，不动小窗。
- 浮窗进出不影响插件：窄屏样式按小窗自己那点宽度走，会话、右侧面板、抽屉照样能用。

## a1.0 / 0.1.30 改了什么

- **右侧边栏回来了**：宿主的面板在窄屏下本来就是全屏的（`RightbarSeat` 自己切 `fullscreen`、宽 `100vw`），是插件以前用 `display:none` 把它藏了。现在它被摆成一整屏：收起时不接触摸、展开时插件顶栏让位、返回键先关它；右上角的「打开右侧边栏」按钮也不再被隐藏。
- **顶栏只剩一行**：☰ 并进会话标题行，标题、`⋯`、右侧面板图标在同一行，插件不再在它们上面单独占 52px；没有标题行的页面（设置、插件、启动页）仍保留那条顶栏。
- **面板里的字放大了**：纯文本正文 15px/24px、带行号的代码 14px/21px，只改右侧面板里的正文，聊天里的代码块不动。
- 打包 tar 里那个 10 KB 的空 `bigrice-ui.tar` 去掉了；自测 121 项全过。

## 0.0.71 / 0.1.28 改了什么

- **预览只对对话内容生效**：之前只要页面上有图片或文件名就会打开浮层，侧边栏头像、插件设置里的文件行、宿主的预览面板都可能被误触。现在加了作用域判断 —— 只有落在会话消息里（`markdown` / `message` / `transcript` 这类容器内）才打开，侧边栏、顶栏、输入栏、设置弹窗、插件自己的卡片一律不接管，点下去交回宿主。
- 自测加了一条「侧边栏里的文件名不触发预览」，共 113 项全过。

## 0.0.70 / 0.1.27 改了什么

- **对话里的图片也走同一个浮层**：以前点内联图片是宿主自己的查看器、点 png/svg 卡片是插件浮层，两种样式不一样；现在点内联图片也用插件浮层（复用页面上已经解码好的图片地址，双指缩放、✕ 关闭、Back 关闭），看起来与点卡片完全一致。
- **关闭键缩小**：右上角圆盘从 44px 收到 32px（✕ 笔画等比缩小、右上角留白同步收一点），接近宿主查看器那个小圆按钮的观感。
- 自测 112 项全过。

## 0.0.68 改了什么

- 预览右上角的关闭键改成**正圆**：这个 WebView 上给 `<button>` 设 `border-radius`（50%/999px 都试过）画出来仍是圆角方形，所以改用内联 SVG 画圆盘（`<circle r="22">`）加一条 ✕ 路径，形状由 SVG 决定。

## 0.0.37 / 0.1.8 改了什么

上一版在真机上暴露三个问题：点工作区行右侧的「…」会把侧边栏关掉、点「查看文件」会先关设置弹窗（看起来像跳回主界面）、导出时写的文件名不生效。这次都修了，并且是**用 adb + CDP 在真机上验证过的**：

- **「…」不再关抽屉**：抽屉的关闭规则改成结构性判断——侧栏里带 `iconButton` 类的按钮（行操作、归档、置顶、搜索、视图、添加工作区）一律不关；`[role=treeitem]` 里只有「会话行」（没有 `aria-expanded`）才关，工作区行只展开。以前只放过 `aria-haspopup/aria-expanded`，而 `工作区“B”的操作` 那个按钮两者都没有。
- **文件浏览回到 bigrice 页签内**：去掉 overlay 层的小窗口和「先关设置弹窗」那套，`FileBrowser` 直接画在「文件」卡片里（带边框、圆角、列表自己滚动），点「查看文件」在下面展开、再点「收起」折回去，设置弹窗全程不关。
- **导出文件名生效**：`sanitizeZipName` 不再把非 ASCII 抹成横线，只替换路径分隔符与 `:*?"<>|` 这些非法字符，也不再加时间戳；重名时由新的 `uniqueZipFile()` 试 `name-2.zip`…`name-999.zip`。真机上导出「我的备份」得到 `Download/我的备份.zip`。
- 自测扩到 **79 项**：行内菜单保持抽屉、工作区行只展开、点会话关抽屉、浏览器在卡片内展开/收起、Back 不再关浏览器。
- 真机验证方式写进了 `bigrice-ui/README.md`：`adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>` + CDP 截图（需要带 `android:debuggable` 的测试包，用 release 证书重签以保留数据）。

## 0.0.36 / 0.1.7 改了什么

上一版把文件浏览直接铺在设置卡片里，列表一长就把设置页撑变形，看着很丑；导入目录也写死在 `/root/A`，用户换个工作区就存错地方。这一版：

- 文件浏览变成**独立小窗口**：点设置里的「查看文件」先关掉设置弹窗（窗口画在应用框架的 overlay 层，而设置弹窗是挂到 `body` 上的，层叠更高），窗口是暗底 + 一张 `min(100%,560px)` 的卡片，文件夹列表有自己的滚动区，不再撑开页面。Back 第一下关窗口。
- **导入目录跟随当前工作区**：插件每 2 秒（以及打开时）从 `uiWorkspace` 读当前会话的 `cwd`，把 `<workspace>/download` 推给 App（`setImportDir`）。Java 侧 `getImportDir/setImportDir/listImportDir` 改成客户机绝对路径语义，新增 `guestRel()` 把 `/root/B/download` 和 `B/download` 归一成 `B/download`，路径解析仍走 `getCanonicalPath()` 防逃逸。
- 设置里不再列出「哪些文件是导入的」——那一列是多余的，只留一个「查看文件」入口和日志查看。
- **导出前先确认文件名**：点「导出 ZIP」先弹一个输入框，预填 `<目录>-YYYYMMDD-HHmm`（例如 `download-20261101-1830`），可以改；App 侧仍会过滤非法字符并补 `.zip` 与时间戳。
- **文件/文件夹都能删**：新桥方法 `deleteEntry(rel)`，走 `resolveInHome` + 递归删除，`/root` 本身拒绝；点一次变「确认删除」，两次才真删。
- 自测 `bigrice-ui/test/logic-test.mjs` 扩到 77 项：文件窗口独立渲染、文件夹进出、图片/文本预览、两次确认删除、勾选计数、导出前重命名、工作区跟随（`setImportDir` 收到 `/root/B/download`）、Back 先关窗口。

## 0.0.35 / 0.1.6 改了什么

「更改位置」在真机上会卡在弹窗里的「正在读取…」——那个弹窗式文件夹浏览器靠 `loadDataWithBaseURL(null, …)` 里的 JS 桥取目录，实际跑不通，于是整条路径换成 App 内的文件浏览：

- 去掉弹窗文件夹选择器和 `pickImportDir/browseWorkspace/chooseWorkspaceDir`，导入路径仍是 `download`（`/root/A/download`），不再可改。
- 设置里的 **bigrice** 页签新增「查看文件」：从客户机 `/root` 开始浏览，「上级」回退，文件夹点进去，文件显示大小；隐藏 `.` 开头的目录，一切路径都过 `getCanonicalPath()` 校验，符号链接跳不出 `/root`。
- 点文件就地预览：图片（png/jpg/webp/gif/bmp，≤12 MB）经 `readImage` 以 data URL 打开，文本（≤512 KB 窗口）经 `readText` 打开；二进制、超大、其它格式都给出明确提示，不会白屏。
- 每一行都能勾选，「导出 ZIP」把勾中的文件/文件夹打成压缩包写进**手机 Download**（API 29+ 走 MediaStore，低版本直写 `Download/` 并声明 `WRITE_EXTERNAL_STORAGE maxSdkVersion=28`）；「保存到」一行显示目标位置，「更改」用系统文件夹选择器（SAF）换目录，选择结果通过 `window.__bigriceExportDir` 回到插件。
- 新桥方法：`listDir/readText/readImage/exportZip/getExportDir/chooseExportDir`。`exportZip` 收的是换行拼接的路径串——WebView 的 JS 桥传数组不可靠，字符串最稳。
- 自测 `bigrice-ui/test/logic-test.mjs` 扩到 69 项：`/root` 列表、进文件夹、图片 data URL 预览、文本预览、勾选计数、导出路径拼接、导出结果提示、更改导出位置、以及导入回调仍会重读列表。

## 0.0.34 / 0.1.5 改了什么

对话框里的「文件」以前在手机上是死的：宿主的命令菜单点下去只是触发一个隐藏 `<input type=file>`，而 `MainActivity` 的主 WebView 从来没实现 `onShowFileChooser`，所以系统文件对话框根本不会弹。现在这条链路通了，同时补了一个文件管理入口：

- 主 WebView 实现 `onShowFileChooser`：把宿主页面要的文件对话框换成系统的（`params.createIntent()` + `startActivityForResult`），多选也支持。
- 选完的文件先拷进**导入文件夹**，再把这些 URI 交回 `<input type=file>`，dsh 照常把它当附件上传——模型能直接读到内容，和桌面端一致。默认文件夹是 `download`，也就是客户机里的 `/root/A/download`；超过 25 MB 的文件只落盘不传，并提示改用 `@` 引用。
- 设置里的 **bigrice** 页签多了「导入文件」卡片：显示当前文件夹的 `/root/A/...` 路径、文件列表（名字 + 大小）、刷新、删除（点一次是「确认删除」，两次才真删）。
- 「更改位置」复用登录那套弹窗：`BigriceHost.pickImportDir()` 打开一个本地文件夹浏览器，选好后通过 `window.__bigriceImportDir(path)` 回到插件，卡片立即刷新。路径存在 `SharedPreferences("bigrice")` 的 `import_dir`，重启不丢。
- 新桥方法：`getImportDir/setImportDir/listImportDir/deleteImportEntry/pickImportDir/browseWorkspace/chooseWorkspaceDir`；所有路径都过一遍 `normalizeImportPath`（拒 `..`、去空段），删除只接受单层名字。
- 自测 `bigrice-ui/test/logic-test.mjs` 扩到 52 项：导入文件夹路径、文件列表与大小、两次点击才删除、「更改位置」调桥、`__bigriceImportDir` 触发重新读取。

## 0.0.33 / 0.1.4 改了什么

设置里多了一个 **bigrice** 页签，用来和 bigrice-app 配合：

- 页签本身只是插件的 `settings.section` 注册项（宿主设置弹窗的导航是按这个槽里的条目生成的），所以不需要改 dsh。
- 页签里是「查看日志」：读 dsh 服务端日志 `files/br/dsh.log`、本次启动的日志快照，以及失败时才会有的 `files/boot.log`；可在几个文件之间切换、手动刷新、打开自动刷新（3 秒）、一键复制。
- 数据走应用的 JS 桥：`MainActivity` 新增 `BigriceHost.readLogs(maxBytes)`，返回 JSON（版本号 + 每个文件的标题、字符数、是否缺失、是否只截到最后一段、正文）。读的是文件尾部，单次最多 1 MB，并且会把 `token=…` 之类的访问令牌打码（这个界面可能被截图发出去）。
- 在普通浏览器里打开 WebUI 时没有这条桥，页签会直接说明"日志只能在 bigrice App 里读"，不会显示一个空框。
- 自测 `bigrice-ui/test/logic-test.mjs` 扩到 42 项：新增页签注册、label、排序，以及渲染组件后点「查看日志 / 切文件 / 复制 / 没有桥」四条路径。
- APK 版本号提到 0.0.33，装机后 `syncPlugin()` 会自动把新插件解包进 rootfs。

## 0.0.30 / 0.1.3 改了什么

聊天里的图片（`read_image` 读到的图、工具生成的图）在手机上只剩一个灰框。起因是插件自己的选择器太宽：

- 宿主的**布局框架**类名是 `mP3x-q_frame`，而图片卡片的类名是 `n-Yh7q_frame`；插件原来用 `[class*='_frame']` 给框架改 `grid-template-columns: 0 minmax(0,1fr) 0 !important`，这条规则同时落到图片卡片上。卡片本身是 `display:grid`，于是 `<img>` 被排进 0 宽的第一列——背景和描边还在，图却永远画不出来（所以浏览器里也一样看不见，跟 WebView 无关）。
- 现在框架规则收窄成 `[class*='_frame']:has(> [class*='centerCol'])`，只命中真正带居中列的那一个；`findFrame()` 也改成先按形状找、再退回"带内联 `grid-template-columns` 的元素"，不会再拿一张图片卡片的宽度去判断是不是手机。
- 自测 `bigrice-ui/test/logic-test.mjs` 加到 28 项：新增「图片卡片不会被当成布局框架」和「框架规则不得是裸的 `_frame`」两条，前者用一张 1280px 宽的假图片卡片挡在框架前面，选错了就会把手机判成桌面。
- APK 版本号跟着提到 0.0.30，装机后 `syncPlugin()` 会自动把新插件解包进 rootfs。

## 0.0.10 / 0.1.2 改了什么

三个真机截图暴露的问题：

- **登录窗口自动缩放**：宿主的登录页是按桌面视口写的。弹出窗口的 WebView 现在打开 `setUseWideViewPort` + `setLoadWithOverviewMode`（外加固定 `textZoom`、关闭缩放控件），页面按卡片宽度重排或整体缩小，不再左右各切掉一截；竖屏卡片也从 `360dp` 放宽到 `screenW-32dp`（上限 420dp）。
- **抽屉不再多出一块**：宿主侧边栏带着桌面轨道宽度（内联 `width:280px`）渲染，抽屉比它宽就会在右边留一条空白。抽屉收窄到 `min(84vw,300px)`，同时插件在手机模式下把侧边栏子树里的内联像素宽度摘掉（并记住原值，回到桌面窗口时还原），面板重新铺满抽屉。
- **设置页页签对齐**：横滚的单行改成换行（`flex-wrap`），左右各 16px 外边距，不再出现「左边留白、右边贴边切一半」；同时把标题行的右内边距单独留给关闭按钮。
- 自测 `bigrice-ui/test/logic-test.mjs` 扩到 25 项，新增「手机模式摘掉内联宽度 / 桌面模式还原」两项。

## 0.0.9 / 0.1.1 改了什么

界面插件不再假设手机是「411dp、中文、竖向」：

- **分辨率**：不再用 `@media (max-width: 767px)` 猜设备，而是量宿主框架的实际宽度（阈值 1024，和 dsh 自己折叠侧边栏的断点一致），点 `data-bigrice-mobile`；高度不足再点 `data-bigrice-short`。
- **语言**：彻底删掉中文字面量匹配。控件的身份靠结构判断（`aria-haspopup`/`aria-expanded` 是菜单触发器，`_panelRow` 是面板条目，`data-sidebar-collapsed` 是抽屉状态），需要显示或比对的文字在点击那一刻从语言包取。英文界面点「More」不再把抽屉关掉——这就是之前那个 bug。
- **登录**：删掉插件自己伪造的「正在打开登录 / 登录暂不可用」页。它会在登录其实已经成功时盖一张失败页；现在只把 `window.open` 转交宿主，反馈由 dsh 自己的登录对话框负责。
- **APK 更新会带上插件更新**：新增 `MainActivity.syncPlugin()`，每次启动对比 APK 内 `bigrice-ui.tar` 与 rootfs 里记录的 SHA-256，不一致就重新解包注册；以前换 APK 后 rootfs 里的旧插件永远不会更新。
- 行为自测 `bigrice-ui/test/logic-test.mjs`（当时 23 项，`node` 直接跑，不需要浏览器）。
